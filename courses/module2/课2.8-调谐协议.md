## 📖 主线正文（整理自视频课 P_16）

### 一、为什么需要"协议"而不是普通讨论

不管你是边学课程边做项目，还是打算将来规划一个项目放进课堂，有一件事是肯定的：**你需要完善你的项目计划**。

- 最初的计划其实只是个草稿，它需要同事或其他人的意见来帮你完善项目
- 所以，把你的计划分享给同事，请他们对设计提些批评意见，请他们帮你填补项目中的一些空白
- 这是复杂的工作，帮助真的能让项目变得更好

**关键区别**：最好的方法不是随便找人聊聊，而是使用一个**协议（Protocol）**。协议就是一种**结构化的对话**——你有机会详细展示你的项目，其他人仔细听你要说什么；然后你也有机会仔细听他们说话，当他们谈论项目、提出建议的时候。当他们真正深入你的项目去思考，并给你提供如何重新规划或完善项目的帮助时，效果最好。

### 二、调谐协议：25 分钟结构化评审

在项目式学习中最流行的协议，真的是最佳实践，叫做**调谐协议（Tuning Protocol）**，有时也叫**关键朋友协议（Critical Friends Protocol）**。这是一个 25 分钟的活动，相对简短，它分成几个部分：

```
调谐协议流程（25 分钟）
─────────────────────────────────────
① 展示（7 分钟）  你展示项目想法，同事保持沉默倾听
② 澄清（5 分钟）  同事问基于事实的澄清性问题
                   （项目多长？学生做什么？什么时候做？）
③ 我喜欢/我好奇（8 分钟）
                   你走出圈子，听，记笔记
                   同事说"我喜欢这个项目的什么""我好奇什么"
④ 圆桌讨论（5 分钟）
                   你回到圈内，谈论听众的建议
                   你反思，不辩解——这是集体活动
─────────────────────────────────────
反馈拿去完善项目 → 真正变成比以前更好的计划
```

### 三、为什么它是"深度倾听的练习"

Tom 强调：调谐协议的核心不是"给建议"，而是**倾听**。

- **你听得越好，你能给同事的帮助就越多**
- 在协议中，你有机会展示你的项目，最多 7 分钟，而其他人都保持沉默——他们的任务不是说话，不是打断，只是听你说
- 这就是为什么说这是一个倾听练习：你听得越多，协议效果就越好

### 四、协议的规则（照做就有效）

只要你注意一些规则，它确实有效：

1. **围成一个圈**，没有干扰，收好手机
2. 你在一个**结构化的协议**里，确保有一些规范
3. 记住**这不是讨论**——所以注意规范，专注于倾听
4. 澄清性问题必须是**基于事实**的（项目有多长？学生在项目里做什么？一年中什么时候做？）——不是评价，不是建议
5. 你在圈外听的时候**不辩解**——听到"我喜欢/我好奇"就记下来，等圆桌讨论再说

### 五、别忘了修剪项目

一旦你做了这些，你可以把反馈拿去完善项目，真正把它变成一个比以前更好的项目计划。

**别忘了，有时候你得修剪项目**：项目可能太长，你可能想做的太多。所以如果你不得不削减项目，别觉得你做错了什么——你可能必须这么做。

> 💡 这是 Tom 给实践者课程的最后一课："去用吧，我觉得你会喜欢的。它不仅是一个完善项目的好方法，也是一个非常有趣、有吸引力、有创意的方式，和同事一起工作，帮他们完善项目，也让他们帮你完善你的项目。"

## 📚 深度阅读（书籍精华）

### 《PBL项目制学习》第 11 章——迭代，建构未来的项目

调谐协议的精神（同行评审、迭代完善）在《PBL项目制学习》第 11 章有系统性阐述：

- **回顾项目成功的关键**：项目结束不是终点，是迭代的起点
- **与同事共同讨论**：把你做项目的经验分享出去，和同事一起讨论哪里做得好、哪里可以改进
- **分享优秀的项目创意**：好的项目方案不应该锁在自己抽屉里，分享出去让更多人受益
- **帮助同事获得项目制学习的新见解**：你既是学习者也是贡献者，同行互评是 PBL 教师成长最快的方式

> 🔗 延伸阅读：《PBL项目制学习》第 11 章 → 知识库检索"迭代"

巴克研究所在《项目学习教师指南》中反复强调：**教师的角色是多重的**——在项目过程中，教师既是设计者、管理者，也是学习者。调谐协议正是"教师作为学习者"的实践：把自己的设计拿出来接受同行的检验。

## 🛠️ 落地工具：调谐协议主持卡

把方法变成动作——主持一场调谐协议时，用这张卡掌控节奏：

```
┌──────────────────────────────────────────────┐
│  调谐协议主持卡（25 分钟）                      │
├──────────────────────────────────────────────┤
│ 会前准备：                                    │
│  □ 围成一圈，无干扰，手机收起                  │
│  □ 明确规范：这不是讨论，是倾听练习            │
│                                              │
│ ① 展示（7 分钟）                             │
│  □ 项目作者展示方案，其他人保持沉默            │
│ ② 澄清（5 分钟）                             │
│  □ 只问事实性问题：多长/谁做/何时/在哪         │
│ ③ 我喜欢 / 我好奇（8 分钟）                  │
│  □ 作者走出圈子，听 + 记笔记                  │
│  □ 同事轮流说"我喜欢…""我好奇…"             │
│ ④ 圆桌讨论（5 分钟）                         │
│  □ 作者回来，谈建议，反思，不辩解             │
│                                              │
│ 会后：拿反馈完善项目，必要时修剪               │
└──────────────────────────────────────────────┘
```

**使用步骤**：
1. 把你的课程方案打印/投影出来
2. 邀 3-5 位同事（或导师团队成员）围圈
3. 严格按 25 分钟流程走，主持人控时
4. 收集"我喜欢/我好奇"笔记，会后整理进方案
5. 修剪过长内容——记住"完成比完美更重要"

> 💡 **研学场景示例**：
> - 布达佩斯展课程设计完成后，召集 3 位导师开调谐协议：7 分钟展示 → 澄清 → 我喜欢/我好奇 → 圆桌
> - 结果可能收获："我好奇'跨时空对话'的成果怎么评估？"→ 促使你补充评价矩阵
> - 西湖水质课设计过长（5 课时）→ 圆桌后决定修剪为 3 课时核心探究

## 📖 案例（调谐协议实践）

### 巴克研究所的"关键朋友"传统

调谐协议源于美国学校改革圈，是**关键朋友小组（Critical Friends Group）**的核心工具。实践要点：

- 小组成员互相是"关键朋友"——既是支持者也是挑战者
- 定期聚会，用协议评审彼此的项目设计、学生作品、教学实践
- 核心信念：**没有人能独自设计出完美的项目，但一群人可以帮助任何人设计出好项目**

**研学落地**：浸思的导师团队可以建立"每两周一次调谐协议"机制——新课程方案、上完的课程复盘、甚至给馆方的合作方案，都走一遍协议流程。

## ✅ 自测（自我检查，做完即看答案）

**题 1（改写）**：你的同事设计了一门"西湖水质"研学课，请你为他的方案写出 2 个"我喜欢"和 2 个"我好奇"。

<details><summary>参考示例（先自己写再看）</summary>

示例：
- 我喜欢：驱动性问题"西湖的水质适合鱼类生存吗"非常本地化，学生有真实感
- 我喜欢：成果是水质报告 + 保护建议书，有真实产品
- 我好奇：学生怎么采集水质数据？采样点如何选择才科学？
- 我好奇：如果检测结果不适合鱼类生存，课程如何收尾（避免"我们失败了"的挫败感）？
</details>

**题 2（判断）**：以下哪个是合格的"澄清性问题"？
A. "你的项目设计得不错，但评估方式我觉得有问题。"
B. "这个项目持续多久？学生每周上几节课？"

<details><summary>答案</summary>

B。A 是评价/建议（应该留到"我喜欢/我好奇"和圆桌讨论环节）；B 是基于事实的澄清问题——调谐协议的澄清环节只允许事实性问题（P_16 原文："这些是基于事实的问题。项目有多长？学生在项目里做什么？"）。
</details>

**题 3（纠错）**：调谐协议进行到"我喜欢/我好奇"环节，作者忍不住插话解释自己的设计。哪里不对？应该怎么做？

<details><summary>答案</summary>

两层问题：(1) 作者在"我喜欢/我好奇"环节应该**走出圈子、保持沉默、只做笔记**（P_16 原文："你走出圈子，你听，你记笔记"）；(2) 插话辩解会破坏"深度倾听"的氛围——同事会顾虑而不敢说真话。正确做法：作者离圈听，同事轮流说"我喜欢/我好奇"，作者记完笔记，到圆桌讨论环节再回应。
</details>

**题 4（自查·本课产出）**：为你正在设计（或刚设计完）的课程方案，写一份"调谐协议邀请函"——包括：项目名称、展示需要几分钟、你希望同事重点听什么、会后你打算怎么处理反馈。

<details><summary>自查指引</summary>

这是本课的实操产出。要点：
- 展示时间控制在 7 分钟（调谐协议标准）
- 明确"希望同事重点听什么"（比如：驱动性问题够不够有力？评估方式是否可行？）
- 会后处理：把"我喜欢/我好奇"笔记分类（采纳/考虑/暂不采纳），更新方案，必要时修剪
- 如果你的团队还没有这个机制，主动提议"两周一次调谐协议"
</details>
