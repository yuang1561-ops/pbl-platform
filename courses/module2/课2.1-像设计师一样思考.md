## 📌 本课导读

Tom Markham 说："这是课程的核心，也是开启优秀项目创作过程的起点。"做 PBL 的第一课，不是学怎么填表格，而是换一种思维方式——**你不再是一个课程规划者，而是一个学习体验的设计师**。同一个主题，用"设计师思维"和"填表思维"做出来的项目，质量天差地别：设计师先问"我想让学生经历什么、带走什么"，再倒着设计全过程。

## 📖 主线正文（整理自视频课 P_4 / P_4.1）

### 一、优秀项目从哪里来？第一个来源：你想象力的深井

Tom 在过去 20 年里走进过 **400 所学校，和 6000 多位老师**交流，他有一个反复出现的观察：每当老师们暂时摘下标准化课程的"眼罩"，开始认真想下面这几个问题时，好项目就冒出来了：

- 我真正想跟学生一起做什么？
- 什么对他们来说会很兴奋？什么对我来说也很兴奋？
- 我怎么能给学习过程带来更多快乐？

他鼓励你也试着这样做——**你想跟学生一起做什么？你觉得他们会真正喜欢？你会怎么创造一个让人难忘的项目？**

那种"难忘"是有画面的：**20 年后你在街上或镇上碰到学生，他们走过来跟你说："哇，你还记得我们做过什么吗？"**——"我记得，太棒了，我从来没忘过。"Tom 说："这才是你在优秀的项目式学习中真正想达到的目标。"

### 二、优秀项目从哪里来？第二个来源：遵循方法论

光有想象力不够，还需要"经过实地测试的方法"：

- PBL 有一套**已经试了 20 年、被证明有效的方法**，你需要遵循这些设计原则
- 这些原则是**灵活的，不是一成不变的**——不管项目是两周、四周、五周还是更长
- 这就是为什么要"像设计师一样思考"：**你不是课程规划者，你是在整体地设计一个学习体验**

Tom 特别强调：不管你做的是基于问题的学习（PBL）、基于挑战的学习（CBL）、基于地点的学习（Place-Based），还是其他 PBL 变体，都别担心——**PBL 本质上是一个非常简单的过程**：

> 把一个有意义的提问或待解决的问题放在学生面前 → 他们去琢磨它 → 他们尽力提供答案 → 他们向你展示学习的证据 → 你看到他们学到了什么，然后给出他们的答案。

### 三、你需要一些工具

- **PBL Global 的工具箱**（就在这次体验里，也可以从 Google Docs 下载）
- **设计指南（Design Guide）**：一个规划指南和表格，带你走完整个规划过程。有 Word 和 PDF 版本，**Word 版本可以直接在里面打字**，按你的需要填写

Tom 的强调："在接下来的两次体验中，**保持你的想象力**。从挑战设计开始，设计你的驱动性问题——这些真的是项目的核心要素，它们会让项目对学生来说更有意义、更有价值、更有用。"

### 四、设计循环全景（P_4.1 核心）

P_4.1 用一张"设计循环"图带你走完整条项目设计之路。开始前 Tom 说了两件事：

1. 如果你之前学过 PBL，会发现某些术语略有不同——但追求高质量 PBL 的人（巴克研究所所称的"黄金标准 PBL"）**用的都是同样的流程**：从头到尾有一个深思熟虑、精心设计的计划，项目才能连贯，最终达到你想要的结果。
2. 随着课程推进，每个设计要素都会深入探讨——现在的目的是**熟悉它们、了解整个旅程**。

**设计循环的六站**：

| 阶段 | 做什么 | 关键问题 |
|------|--------|----------|
| ① 识别挑战 | 灵感部分、想象部分，想出好点子 | 这个点子能让你兴奋，也能让学生兴奋、激发动力吗？ |
| ② 构思驱动性问题 | 设计循环的核心阶段，想出问题并不断打磨 | 第一个问题往往不够好，如何优化？ |
| ③ 跳到终点 | 直接看项目的终点：结果是什么？想达成什么？ | 你想让学生产出什么作品？他们会做什么？ |
| ④ 逆向设计 | 从终点倒推：构建评估体系 | 你必须在项目启动前就有一个完整的评估计划 |
| ⑤ 以终为始地启动 | 正确启动项目 | 怎么让团队投入？怎么组建团队？怎么激发兴趣？怎么为最大化学习效果设置整个流程？ |
| ⑥ 中段 + 以精通收尾 | 学生设计、解决问题、团队合作、起草方案；教师引导、辅导、做直接教学 | 给足时间把工作做好；有评分标准；不允许任何马虎的工作 |

**"以精通收尾"为什么关键**：让学生在这个过程结束时感觉**他们掌握了项目、做出了好作品、做了一些他们能引以为豪的事情**。这需要你关注项目结尾如何形成，以及是否达到了你期望的表现水平。

### 五、优势导向的 PBL：设计循环的隐藏彩蛋

Tom 用一张幻灯片提醒：我们用的是**优势导向的 PBL 版本（strengths-based PBL）**——在设计过程的每个节点，你都可以思考**你希望学生发展哪些优势**，比如好奇心、韧性、坚持这些我们今天认为重要的优势。

PBL 设计流程真的很适合：
- **激发**学生的这些优势
- 让他们**练习**
- 给你**机会给他们反馈**

"PBL 和优势导向的工作配合得很好，这就是设计循环如何实现这一点。"

### 六、给设计者的三句叮嘱

1. **保持想象力**——好点子先于好表格，先想"我想和学生一起做什么"再谈流程
2. **过程是灵活的**——设计原则不是锁链，是导航
3. **终点先行**——评估计划必须在项目启动前就位

## 📚 深度阅读（书籍精华）

### 巴克《项目学习教师指南》第 4 章——规划项目过程

**核心比喻**：规划项目过程就是**绘制一幅"项目地图"（project map）**。它类似于教案设计，但要反映出项目**可扩展性**的特征和对项目的**结构化设计**。一个设计很好的项目计划不只是一组活动序列说明，它本身是一个设计方案——支持和引导学生创造出项目作品。项目地图帮你确定学生必备的技能、确定项目进度表、收集资料以支持关键学习活动。

**规划的关键步骤**：

1. **组织项目任务与活动**：根据项目作品把项目分解成一系列任务。项目启动前先分析要求完成的项目作品，再审视学生："他们的知识储备是否能够支持他们取得项目成功？"例如项目中有展览和口头陈述——学生学过如何做口头陈述吗？知道如何做采访吗？知道如何在互联网上查阅资料吗？**只有能十分确定地回答"是"，才能开始真正的项目学习**；否则先花时间帮助学生准备和练习这些关键技能——这最终会为项目节省时间、增加成功概率。这个过程叫**搭脚手架（scaffolding）**，但注意：这并不意味着把项目推迟到学年最后阶段——**项目是要把学生带入一种不同的课程学习中，有时最好的学习就是让他们经历整个过程**。
2. **启动项目**：启动方式多种多样——课堂讨论、现场参观、阅读一篇文章、听嘉宾讲座、某个活动，这些统称**"启动事件"（entry event）**。基于问题的学习中常用**"启动文档"（entry document）**，描述背景、说明要解决的问题、定义学生角色和任务、设定对成功完成项目的期望。无论用事件还是文档启动，**关键目标**是让学生迅速理解：项目的范围、要求完成的项目作品、项目过程中的评价方法与标准。
3. **收集资源**：提前计划好资料准备工作——准备网站清单、复印项目表格、预约计算机机房、预先吸纳要观摩最终展览的成年人。资源包括信息（图书、人、互联网）、物品（笔记本、建模用纸、展板）、技术工具（计算机、照相机、打印机），并**为学生留出时间学习如何有效使用资源**。

**画出项目"故事板"**：当我们想好项目的主要活动时，就要考虑如何可视化地描述整个项目包含的所有工作——可以用**泡泡图（bubble diagram）、流程图（flow chart）或故事板（storyboard）**的形式，为项目制订进度表，确定里程碑、任务和其他重要活动的预计日期。项目"故事板"包括**时间进度表、主要的活动和重要里程碑**。

**7 年级学生历史项目故事板实例**（4 周多媒体项目）：启动 Anne Frank 项目并介绍驱动问题（3月3日）→ 组建团队、选择主题、调研阅读（3月5日）→ 整理论文草稿（3月12日）→ 制订项目网络计划图、设计口头陈述提纲（3月17日）→ 批准计划图、制作多媒体作品（3月19日）→ 口头陈述演练、完成作品（3月24日）→ 最终展示（3月28日）→ 项目回顾（3月31日）。同时列出资源需求：**计算机机房（3月17~24日）、多功能教室（3月28日）**。

**项目活动与任务分解参考**（摘自 John Thomas 著作，六类）：计划（任务分工表、项目进度表、流程图、概念图）、问题分解（头脑风暴、问题分类、设计正式模型）、扩充知识（向专家学习、正式采访、小组讨论或辩论、问卷调查）、协调（解决小组争执、按规则开会、点子箱/待办清单、切块拼接法）、评价（设计评价表、成本—收益分析、按现实要求评价作品、为立场辩护）、沟通（陈述、报道事件、向新手传授技能、设计图表、针对不同听众调整讲座）。

## 🛠️ 落地工具：故事板（50工具 工具11）

把"设计地图"变成一张可视化的画布：

```
┌───────────────────────────────────────────────┐
│  故事板（工具11）——三部分                        │
├───────────────────────────────────────────────┤
│ 【背景区】项目活动发生的场景、学生年龄、分组情况、  │
│   主要项目活动和学习目标                         │
│ 【图画区】把项目活动要点画出来（形式自选：          │
│   手绘/电子），画出各阶段重要的场景、活动、人物    │
│ 【描述区】文字描述活动要点：步骤、提问要点、活动内容│
├───────────────────────────────────────────────┤
│  使用场景：教学设计第3模块（计划筹备）预想关键节点；  │
│  也可在实施、复盘阶段作为启发深入探究/总结反思的工具 │
└───────────────────────────────────────────────┘
```

**使用步骤**：
1. 写背景区：项目发生在什么场景？学生多大？怎么分组？学习目标是什么？
2. 拆阶段：按项目进程划分板块（启动活动 / 探究活动1·2·3… / 反馈修改 / 成果展示）
3. 画图画区：每个板块画出关键场景（人物、动作、环境），旁边写要点
4. 写描述区：把每个板块的活动步骤、提问要点、活动内容写清楚
5. 教师也可以**教学生用故事板**——学生在拍摄视频、举办博物馆展览等活动中，用它规划拍摄场景、陈列细节，锻炼资料收集、材料组织和表达能力

> 💡 **研学场景示例**（把 PBL 方法落到你的业务）：
> - **博物馆讲解员项目**（50工具原文案例）：背景=教室+博物馆，6-9 岁，5人1组共6组、8课时。故事板板块：启动活动（播放讲解视频引出驱动问题"如果你是讲解员，你怎么给大家讲解？"）→ 探究1认识讲解员职业（以"应聘志愿者讲解员"方式）→ 探究2绘制展厅平面图 → 探究3绘制出行线路图（地铁到博物馆）→ 探究4用 5W1H 描述展品 → 反馈修改 → 成果展示（实地讲解/模拟讲解/藏宝游戏）
> - **良渚研学项目**：背景=良渚博物院+教室，板块：启动（玉琮照片悬念："它为什么是权力的象征？"）→ 探究1良渚古城沙盘复原 → 探究2玉器纹饰拓印 → 探究3"小小考古学家"档案卡 → 成果展示（为家长团做一次展厅导览）

## 📖 案例（行动者手册）

### "设计思维校本课程"：一套五步法，两次实践，一次蜕变

**背景**：深圳市光明区光明中学的高中校本课程，每周一课时（16:50~17:30），共 13 周。教师方庆参加了设计思维培训后，先后实践了两期《设计思维》校本课程——**第一期不太成功，第二期比较成功**。

**过程**：设计思维五步法——**同理 → 定义 → 创想 → 原型 → 测试**。课程用一个小例子讲透五步：班上同学手臂受伤了，需要设计防护方案——感同身受是"同理"；做安全防护是"定义需求"；想出好几个方案是"创想"；调整座位、做出简易防护网是"原型"；让他试一下有没有效果是"测试"。课程还设计了**"吸管船"团建**（每人至少画4个设计图→交流选定→实施→调整再实践，40分钟完成）和"确认彼此眼神"破冰游戏。学生作品包括 3D 打印的《手带式电脑》（为夜跑场景涂荧光漆）、激光雕刻喇叭、《懒人牙刷》等。**测试环节**：一个女生做的粉笔盒测试时发现 43 个大粉笔头漏下去，于是把中间的筛子做密了一点。

**结果**：第一期只有粉笔盒比较符合要求，其他学生大多失败；第二期却设计制作出一系列作品，五六个小发明获得区级和市级奖。

**启示**：成功的原因有二——(1) 老师重视**文化环境创设与资源获取**（创客实践室、平等真诚互助的氛围）；(2) **学生助教团队**（5 名懂编程、电路、3D 打印、激光雕刻的学生提前接受培训，在课程中做榜样示范）。对设计者而言：**不要想得非常完善之后再行动**——有了构想，哪怕想得不是很清楚、条件不够，只要方向是对的，就立马行动，通过行动检验设想、获得反馈、迭代升级。这正是 P_4 说的"像设计师一样思考"：把设计周期（识别挑战→原型→测试→迭代）跑起来，而不是停在纸面上。

**题 3（判断）**：一位老师做完项目计划后说："我的故事板画好了——每个格子写满了活动名称，从周一到周五排得满满的。"这个故事板有什么问题？

<details><summary>答案</summary>

两层问题：(1) **只有活动没有地图**——巴克第4章说故事板要包含"时间进度表、主要的活动和重要里程碑"，只写活动名称就丢了里程碑（草稿完成日期、排练日期、作品完工日期）和资源需求（机房、教室、器材）；(2) **只有文字没有画面**——工具11 故事板分背景区/图画区/描述区，图画区的作用是让人"快速领会项目要点"，全文字就成了普通日程表，失去了可视化带来的全局感和场景感，学生也看不懂项目重点和难点。修正：补上"项目地图"要素——每个格子写清楚是什么阶段（启动/探究/反馈/展示）、关键活动、里程碑节点、所需资源，并用图画表达关键场景。
</details>

**题 4（自查·本课产出）**：为你自己的一个课程（或研学产品）画一张"设计地图"：
1. 用一句话写"意图"：20 年后学生遇到你，会记得什么？
2. 按设计循环六站走一遍：识别挑战→驱动性问题→终点（作品）→评估→启动→中段与收尾
3. 用工具 11 故事板的三部分（背景/图画/描述）把全过程可视化

<details><summary>自查指引</summary>

这是本课最重要的练习（P_4 的产出要求）。如果卡住：
- 写不出"意图"→ 回到"想象力的深井"四个问题：我想和学生一起做什么？什么让他们兴奋？什么让我也兴奋？怎么带来更多快乐？
- 分不清阶段 → 用巴克的项目活动与任务分解表（计划/问题分解/扩充知识/协调/评价/沟通六类）对照自己的活动
- 故事板全是文字 → 试着每个板块画一个简单小图（火柴人也可以），图画会逼你想清楚"场景是什么样"
- 检查：地图上有没有里程碑日期？有没有资源清单？有没有"以精通收尾"的环节？
</details>
