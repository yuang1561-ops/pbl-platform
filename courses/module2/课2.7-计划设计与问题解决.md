## 📌 本课导读

Tom Markham 开了一个玩笑："这个体验的标题是'设计思维与问题解决的规划'，但我觉得，这个体验的标题应该是**'为泥泞中段做规划'**。"他观察到一个长期痛点：老师们能提出很好的驱动性问题，也能想出学生最后要产出什么成果，**但中间部分就成了一个谜**——该用多少直接教学？该用多少团队合作？学生在项目中间到底做什么？他的回答是：**泥泞中段不再需要存在了**——随着设计思维越来越突出，那个中段被设计思维填满了。

## 📖 主线正文（整理自视频课 P_9）

### 一、"泥泞中段"之谜

多年来 Tom 看到：老师们能提出很好的驱动性问题，也能想出学生最后要产出什么样的成果。**但中间部分就成了个谜**：

- 他们该用多少直接教学？
- 该用多少团队合作？
- 学生在项目中间到底做什么？

"这对老师来说一直是个问题。"

### 二、答案：设计思维填满中段

"嗯，我觉得现在这个问题已经清楚了：**泥泞中段不再需要存在了。**"

- 随着设计思维越来越突出，越来越多的老师在使用它，Tom 明显看到：**那个中段被设计思维填满了**
- **当团队和项目式学习经历问题解决的过程时，他们实际上是在经历设计过程**
- 所以：**当你有了驱动性问题和设计过程，基本上就有了一个项目式学习项目**

### 三、要做到这一点，你得准备好三件事（P_9 核心）

**第一件：你得教学生设计循环**
- **大多数学生不知道这个**——这不是学校通常教的东西。也许他们幸运地上过用设计思维的课，但很可能没有
- 所以你得**教他们怎么用设计过程，并把它应用到团队合作中**——这是你需要做的一件事

**第二件：你得小心安排时间**
- **项目式学习中的团队合作总是需要时间**——实际花的时间比你想象的多，有时多到让老师觉得不舒服
- 因为这是不可避免的，不管你是大人还是孩子，都一样：**你把学生或人放进一个团队，他们得花大概 10 到 15 分钟才开始讨论要做什么**
- 这不是一个即时的过程——"这是我说的那种**缓慢的学习过程**"

**第三件：在项目计划里找设计思维的落点**
- 当你开始推进项目计划并思考团队合作时，试着弄清楚：**我能在哪里用上设计思维？**

### 四、设计思维是"全课程的工具"，不只是 STEM

Tom 要加最后一点：

- 设计思维跟 STEM 科目有关——科学、技术、工程，**设计思维实际上就是从这些领域出来的**
- **但设计思维可以应用到任何地方**，比如社会科学和人文学科的想法
- **如果你有任何想改进并产出东西的事情，那都是设计循环的一部分**——所以你可以用在任何科目、任何课程里
- "**别把它只当成 STEM 工具，它真的是一个全课程的工具。**"

### 五、P_9 的行动清单

1. 把设计循环教给学生（同理→定义→创想→原型→测试，即课 2.1 的设计循环在团队问题解决中的应用）
2. 为团队合作预留"缓慢启动"的时间（10-15 分钟起步很正常）
3. 在每个项目阶段问自己"设计思维用在哪"
4. 把设计思维当成全课程工具，而不是 STEM 专属

## 📚 深度阅读（书籍精华）

### 《PBL项目制学习》第 6 章——学习项目管理策略

**团队分工与本地资源**：如果你与教学团队合作，要想想如何划分责任——你们的强项和兴趣是什么？每个人负责哪些任务？苏黎世国际学校 1 年级团队建造"自然历史快闪博物馆"时，涉及具体技能（纸浆工艺制作模型、技术应用到展品设计），教师就"分而治之"。实地探索三次出行各有目的：早期参观野生动物园构建背景知识（这里展示了哪些动物？）、中期去池塘训练观察能力（他们注意到了什么？想要知道什么？）、后期再访博物馆训练对展览设计的批判性思考（讲解员如何节选信息、如何让信息变得有意思）。卡蕾·霍克老师说：项目制学习中的实地调查"更多的是一起去探索"——学生观察到"有脚的蛇"（其实是蝾螈），开启全新研究思路。

**设置项目重要节点和截止日期**：**教育学生成为时间的有效管理者，应该是任何项目的首要目标**——这项技能将支持学生整个求学生涯乃至之后的生活。在第 5 章建议制订**项目日历**并设置几个重要时间节点；**把项目日历分享给学生，使截止日期可视化**，他们会更加注重时间把控、提前做计划、调整进度、防止落后。**也可以把项目日历分享给家长**（班级网站、项目博客或项目周报电子邮件）。经验丰富的项目制学习老手会在教室设置一面"**项目墙**"或显眼的公告栏，把所有重要计划资源和注意事项放在可见的地方。

**制定形成性评估策略**：教育博主比安卡·休斯组织项目制学习交流会，参与者谈及的挑战之一是**如何防止项目中的形成性评估变成例行公事**。她在博文列表里征集"妙不可言的形成性评估构想"，收到的创意包括使用迷你白板、让学生用 RSA 动画风格作画捕捉想法。

**尝试不同的团队组合模式**：一位运用 PBL 多年的教师认为学生倾向跟最合拍的同伴组队，但她仍会干预、定期重新划分团队，一贯做法是把**特征互补**的学生组合在一起（组织能力强的 + 擅长科技的）。学生有时独立完成任务的一部分，有时结对/小组，偶尔全班合作。用问卷调查发现学生隐藏才能；让学生制作个人简历在项目组中申请特定角色；团队合约承诺职责与承担危害团队利益的后果。朱兰娜·博伊德老师无意中听到两个 5 年级学生的对话："我觉得跟你一起合作挺难的，因为你很专横。""没错，我确实如此，但我想我能控制住自己。"——这坦诚的对话正是学生发展人际交往能力的标志。

**设立补给工作区**：如果项目实施中出现知识或技能脱节，就规划可用的补给或"保障性"教学活动，甚至让学生来规划。海洋学与巡航项目中教师设立"学习打水手结"的工作区；机器人项目中学生用 CodeHS、Code Academy、Scratch 在线编程拓展经验。**你的补给工作区会有什么呢？**

**科技手段管理项目**：教师需求——沟通工具、变更通知工具、提供资源的方法、管理学习成果的系统、支持高效学习环境的结构、评估工具（衡量有效性、评估任务分配均衡度、及时反馈）。学生需求——管理时间和工作流的系统、管理物料和草案的系统、协同合作工具、寻求协助的方法、获取和使用反馈的方法、循环工作方式。基础工具从可获取的开始：区域服务器、学习管理系统（Moodle、Blackboard、教育魔豆、Schoology、Google Classroom）、**维基（保留历史版本，教师可查历史记录衡量项目活动进展与合作情况）**、博客（传达项目进展和重要节点、学生独立博客+互评）、专有网络空间（WordPress/Drupal）。莉萨·帕里希把维基看作项目"基地"："因为学生可以在维基上自由地使用多种工具来进行项目合作和创作，所以维基是托管所有项目组成部分的最佳场所。"

## 🛠️ 落地工具：须知表（工具5）+ 工作计划表（工具10）

**工具 5 须知表（need-to-knows）**——把"待解决的问题"拆成学生自己能提出的问题：

```
┌───────────────────────────────────────────────┐
│  须知表（工具5）——三列                          │
├───────────────────────────────────────────────┤
│  待解决的问题  │ 已经知道的内容  │ 需要知道的问题 │
│  （项目最终    │ （分析现状，    │ （把抽象变具体、 │
│   目标，以终    │  明确自己学习    │  把大问题化小，  │
│   为始不偏航） │  步调）        │  继续拆解）     │
└───────────────────────────────────────────────┘
```

**使用步骤**（引导者+参与者；引导者不评判，只记录）：
1. **理解"待解决的问题"**：先看第一列，确保所有学生理解。例："北京——中轴线上的城市"项目驱动问题是"50 年后的北京，还是不是中轴线上的城市？"先请学生提出对问题本身的疑惑（为什么是 50 年不是 100 年？为什么要关注中轴线？）
2. **明确"已经知道的内容"**：学生是否已知道"北京中轴线正在申请世界文化遗产""北京曾是以中轴线为基准建造的都城"？知识参差时可停下来组织统一讲解或同伴互讲
3. **探讨"需要知道的问题"**：引导者用引导问题激发讨论（"过去 50 年变化非常显著，50 年后北京城还会以中轴线为基准吗？我们需要知道哪些信息？"），参与者自由发言，快速记录关键词——**此时无须考虑问题品质**
4. **问题总结和梳理**：把关键词整理成完整问句（"建筑""城市的中心在哪里"→"以中轴线为基准的城市建筑布局有什么特点？"）
5. **识别问题**：其一，区分开放问题（无标准答案，进入下一轮拆解）和封闭问题（查资料能答，确定权威来源后分配任务找答案）；其二，区分有关问题（和核心驱动问题关联，保留）和无关问题（如"中轴线上的故宫有多少个大殿"——舍弃）；其三，**对问题优先级排序，判断从属和依赖关系**（"北京近 50 年城市中心变化"是预测未来的先决问题，先把历史研究清楚才能有依据地预测）

**何时使用**：第三模块"计划筹备、整合资源"制订教学计划；第六模块"解决问题、产出成果"学生头脑风暴；自主学习梳理思路。

**工具 10 工作计划表**——把项目变成可执行的时间表：

```
┌───────────────────────────────────────────────┐
│  工作计划表（工具10）                           │
├───────────────────────────────────────────────┤
│  主任务 │ 主产品 │ 子任务 │ 子产品 │ 课上/课下 │ 所需课时 │ 截止日期 │ 负责人 │ 资源需求 │
├───────────────────────────────────────────────┤
│ 制订访谈 │ 访谈计 │ 确立访谈│ 访谈目标│ 课上   │ 1课时  │ 4月2日 │ 教师  │ 讨论工具 │
│ 计划   │ 划书   │ 目标   │        │        │        │        │      │ 白板    │
└───────────────────────────────────────────────┘
```

**使用步骤**：
1. **拆解**：以"问题-任务-产品对应表"（工具8）的主任务和主产品为主要框架，把主任务拆出子任务并列出子产品（"人物访谈"项目：制订访谈计划 → 确立访谈目标/了解访谈人物/确立访谈提纲，各自对应访谈目标/人物分析报告/访谈提纲）
2. **定课上/课下**：需要团队共同商议的任务安排课上（确立访谈目标 1 课时），可自主研究的安排课下（人物资料分析）
3. **定截止日期**：按项目整体规划和学校授课安排确定；需要深入学习研究的任务要给足时间（人物背景研究至少 5 天）
4. **定负责人**：把控方向的由教师负责（确立访谈目标），具体操作按"小组角色设定表"（工具4）的第一角色负责
5. **规划资源**：师生一起规划每个子任务所需资源（人物背景资料学生难以自行获取，教师准备"学习资源包"并审核）

**⚠️ 纪律**：**工作计划表一旦确立，不能随意修改，以免造成混乱**——建议项目负责教师拥有修改权，其他成员拥有浏览权和建议修改权，问题与建议及时反馈给负责教师。

> 💡 **研学场景示例**（把 PBL 方法落到你的业务）：
> - **良渚研学须知表**：待解决问题="如何为良渚玉器设计一场儿童展览？"；已经知道=良渚在杭州、玉琮是礼器；需要知道=玉器怎么做出来的？为什么是权力象征？儿童喜欢什么讲解方式？→ 开放问题进入第二轮拆解（玉器工艺组/策展组/游戏设计组各填一张嵌套须知表）
> - **西湖水质研学工作计划表**：主任务=完成水质检测报告；子任务=采样（课上 2 课时，负责人采样员，资源=采样瓶）、检测（课上 2 课时，检测员，pH 试纸/传感器）、数据分析（课下 4 小时，数据分析师，电子表格）、报告撰写（课下 3 小时，主笔，模板）；截止日期倒排到成果发布会前 3 天
> - **布达佩斯展导览词项目**：主任务=制作导览词；子任务=选画（课上）、查证背景（课下，资料包）、写稿（课下）、排练（课上 2 课时）；项目墙上张贴工作计划表，向家长群同步项目日历，节点：初稿提交日→同伴互评日→展场实测日

## 📖 案例（其他书）

### "狂狮之傲"（Lion Pride）：一个全校项目的计划与问题解决

**背景**：美国俄克拉荷马州豪镇高中，一个由全体教员设计的全校性项目，原本以全体教职工团队合作为目的，最终全体学生都参与进来。

**过程**：项目始于驱动性问题——"**如何才能让我们的学校变得更好？**"，促使学生进行批判性和创造性思考。学生团队知道他们将有望借此提案**赢得 1,000 美元奖金**。团队分配人员**有意将不同年级和不同能力的学生混合分组**——项目开始时，学生先花时间跟队友熟悉（初期的团建活动打造畅所欲言的氛围：给队伍命名、制作宣传横幅），这些前期活动为后面做铺垫，有助于头脑风暴，最终一致通过某个具体提案。在最后的推介环节，**评委们被学生的表现所打动，决定把奖金翻倍，以资助两个项目的开展**。

**结果**：一个意外的收获是学生重新了解了彼此的优势。学区科技导师塔米·帕克斯说："同学们学会了如何进行合作之后，整个学校的氛围就发生了转变。"即使是那些从前有行为问题的学生，"现在也看到了团队合作的巨大价值，他们意识到自己在学习中也能有话语权。"

**启示**：对照 P_9——驱动性问题有了、终点（提案+奖金）有了，**中段靠什么填满？靠团队建设（命名/横幅/头脑风暴）、混合编队（不同年级不同能力）、项目预算（1,000 美元真实奖金）和推介准备**。对照 epub 第 6 章——"有效的项目管理需要将风险最小化，但同时也要将机遇最大化"；"在项目开始时，先让学生制定出一份团队合约，承诺履行合约上所规定的团队成员职责，以及承担危害团队利益的后果"。计划不是锁死流程，而是**为"让每个学生都有话语权"创造条件**。

B. 需要团队商议的排课上（1 课时），资料研究排课下（给足 5 天），方向把关由教师负责、具体操作由角色表里的第一角色负责，截止日期倒排

<details><summary>答案</summary>

B。依据工具10 使用步骤：任务要区分课上/课下（B 做到了，A 全压课上）、截止日期要考虑学习深度（工具10 原文：人物背景研究"短短一两天是不够的，至少五天"）、负责人要分工（教师管方向、学生管操作）、日期要倒排。A 的"3 天交全部成果"既没给足研究时间，也没有里程碑节奏，容易出现"活动多、学习少"。
</details>

**题 3（判断）**：一位老师说："项目计划表已经排好了，每个学生每天做什么写得清清楚楚，照着做就行，这样最不容易出错。"这个做法有什么问题？

<details><summary>答案</summary>

两层问题：(1) **违背"让学生做决定"的原则**——epub 第 4 章"项目设计中易犯的 6 大错误"第 4 条就是"学习步骤过于详尽"：最好的项目是让学生在学习中做决定，步骤过于详尽会使学习成果可预见且十分局限；(2) **须知表的价值被抹掉**——工具5 的精神是"教师不是把拆解好的问题直接抛给学生，而是让学生通过须知表自己拆解和思考"，所有问题都应该是学生自己提出的。修正：计划表定框架（主任务、里程碑、截止日期），把"怎么完成"的空间留给学生——用须知表拆问题、用角色表分任务、用补给工作区补技能，教师守住修改权而不是包办一切。
</details>

**题 4（自查·本课产出）**：为你自己的课程/研学产品完成"计划设计"：
1. 用须知表（工具5）和学生们拆解一次核心驱动问题，标出开放/封闭、有关/无关问题
2. 用工作计划表（工具10）排出主任务→子任务→子产品→课时→截止日期→负责人→资源
3. 把计划张贴到"项目墙"并向家长同步项目日历（epub 第 6 章做法）
