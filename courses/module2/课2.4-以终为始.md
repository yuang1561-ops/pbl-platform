## 📌 本课导读

Tom Markham 管这节课叫他的"顿悟时刻"：他注意到老师们规划项目时常卡住——创意部分（想法、挑战、驱动性问题）讨论得热火朝天，一到"项目机制和后勤"就停住了。他的解决办法出奇简单：**别从中段开始规划，从结果开始。** 一旦驱动性问题可接受，立刻跳到终点：学生会产出什么？需要什么技能和知识才能到达那里？然后倒着工作。这就是"以终为始"（backward design / 逆向设计）。

本课整合三套资料：**视频课 P_7/P_7.1** 讲倒推规划的三个领域（表现、技能、掌握任务）、**巴克《教师指南》第 1 章**讲"确立项目的设计标准"（6A 法则）和"创设理想的学习氛围"、**《50个工具》工具 9** 给"评价矩阵"落地工具。学完本课，你应该能写出自己项目的终点、标准与评价方案。

## 📖 主线正文（内容源自 PBL Global 大师课）

### 一、顿悟时刻："从结果开始"

Tom 说："我被认为是项目式学习方面的专家……但事实是，我一直在不断学习，主要通过和老师们的对话来学习。"偶尔他会遇到所谓的"顿悟时刻"——这次的经验叫做"**从结果开始**"。

**老师们卡在哪**：规划项目时，老师们会讨论创意部分——想法、挑战、驱动性问题、那些打算在项目中做的很棒的事情——然后就会卡住。而规划项目通常很有趣，**但到了某个点，你真的得转向项目的机制或后勤安排**："这个想法到底要怎么付诸实践？"

**Tom 的解法**：当你已经找到一个**能接受、觉得可行的驱动性问题**之后（顺便说一句，这些在项目进行中是可以改变的），立刻开始看项目的终点：
- 学生会产出什么？你会做什么样的作品？
- 他们需要什么样的技能才能到达那里？
- 什么样的内容？他们需要什么样的知识才能到达那里？

一旦心里有了那个作品和项目最终如何结束的感觉，**那就变成了一个倒推规划的过程**。

### 二、倒推规划：在三个领域里倒着工作

如果你做过倒推规划或"理解性设计"（Understanding by Design），会觉得熟悉——**你真的开始倒着工作，而且在三个领域里倒着工作**：

**第一个领域：表现（Performance）**
- 他们最后要怎么表现？会做展示还是公开演讲？
- 他们要面对什么样的观众？那个表现会是什么样子？

**第二个领域：技能（Skills）**
- 他们会用到合作技能、演讲技能吗？
- 你会关注创造力、批判性思维吗？
- 你为项目考虑了哪些技能，怎么把它融入项目设计，这样学生就能学习和练习这些技能，并在项目结束时用到它们？

**第三个领域："掌握任务"（Mastery Tasks），也就是标准**
- 学生需要掌握的核心内容、核心知识、核心信息是什么？
- 他们需要积累词汇吗？需要了解概念吗？需要为考试做准备吗？

这就是你真正专注于项目的地方：**确保你融入了内容知识和必须在项目过程中处理的掌握任务**。

### 三、项目不是甜点

Tom 用一句扎心的话点破 PBL 最大的批评："**记住，项目不是甜点（dessert）。**它们不是我们在教完课程之后才做的事情——它们是课程的一部分。**你通过项目来教课程。**"

- 所以如果你通过项目来教课程，就必须融入核心内容或掌握任务
- 有很多项目做过，很有趣、很吸引人，学生们很喜欢——**但它们没有处理学生需要考试的确切内容标准**，这是多年来对项目式学习的批评之一
- **我们知道怎么修复**：非常密切关注项目中要包含什么内容，以及怎么教
- 这可以通过**作业、论文、测验、考试、直接教学、讲座**，以及你教学时用的所有传统工具来教

有一次有个老师问他："项目期间我能布置作业吗？"Tom 的回答是："**是的，你可以做所有平时当老师时做的传统事情，只要把它们融入项目里就行。**"总体目标是：让学生参与一个引人入胜的、以表现驱动的问题解决过程，但他们在过程中需要掌握知识，你也得给他们留下核心知识。

### 四、退一步审视项目（P_7.1 前半）

P_7.1 一开始 Tom 道歉说"这部分可能有点重复"，但他真的想强调这个想法：**退一步看项目，审视它，努力想象你到底想达成什么**。要问自己一串问题：

- 结局会是什么样的？会是**戏剧性的、令人难忘**的吗？
- 你会怎么**赋能你的团队**？怎么真正指导他们走向成功？
- 你能**预见到哪些问题**？
- 你会选什么内容？项目结束时学生需要知道什么？在内容方面你会坚持什么？
- 你会怎么整合**二十一世纪技能**？
- 你的计划是什么？
- 最后，**如果项目开始变得太大，就修剪一下**——你不想做得过火，有时候你得修剪

### 五、表现：高表现的两个关键

一旦你开始看表现，想想：
- 他们会产出什么？他们会为什么兴奋？他们会怎么展示？**为什么这会令人难忘？**
- 重要的是，他们会怎么和**社区成员或教室外的成年人互动**？

**记住：成人互动、公开表演（adult interaction, public performance）——这是项目式学习中高表现的两个关键。**想清楚你怎么做到这些。

### 六、技能与掌握任务：把它们写下来

**技能方面**：
- 哪些技能和压力（skill and stress）是他们必须学的关键？这些会随着一年时间而变化——有时候合作是初始技能，然后是展示和批判性思维
- 你会怎么为他们做**差异化**？他们会在项目中怎么练习个人优势和技能？

**掌握任务方面（Tom 强调要详细覆盖）**：
1. **确定学生在这个项目中要学的核心标准**——写下来，知道它们是什么，告诉学生"这是他们需要知道的，这是他们在项目中要学的"
2. 哪些主题、概念、大想法对你重要？**哪两三个概念或大想法，你希望学生最后带走？**——一些他们会记住的、一些他们能在生活中应用的、对他们有意义的知识
3. 如果需要用**基于标准的评分**方法，那就用——把每个核心标准链接到评估形式，这样你确切知道学生在学什么
4. 确定那些评估方法：测试、考试、小测验、论文、报告……**所有你通常用来评估的工具都可以成为你评估计划的一部分**。你需要一个计划，特别是专注于标准的计划

> Tom 预告："我们会在'为成长而评估'的体验中多谈这个，但你需要一个计划。"

## 📚 深度阅读（书籍精华）

### 巴克《项目学习教师指南》第 1 章——确立项目的设计标准

**好的项目不是靠运气，而是有一套重要的标准**。这套简单明了的标准就是本章"点子库"中提到的 **"6A 法则"**：一个项目应该包含——

| A | 英文 | 含义 |
|---|------|------|
| 真实性 | Authenticity | 项目反映真实世界的问题与任务 |
| 学术严谨性 | Academic Rigor | 指向学科核心内容与高级思维 |
| 学以致用 | Applied Learning | 把所学应用到真实问题解决中 |
| 积极的探索 | Active Exploration | 学生主动调查、研究、实践 |
| 与成年人的联系 | Adult Connection | 与校外成年人/专家互动 |
| 评价的实际应用 | Assessment Practice | 评价真实、清晰、贯穿始终 |

**规划项目时的自检清单**：这个项目是否——符合课程标准的要求？能够吸引学生参与、调动积极性？能让学生聚焦到对关键问题的理解？能鼓励学生具有高级思维（参考第三章布卢姆思维层次分类法）？教授并加强读写的基本技能？能让每一位学生都有成就感？使用清晰、精确的评价方法？要求对技术的灵活使用？处理真实的问题？

**小心陷阱**：不要单纯根据"学生是否能够在项目中锻炼思维"来判断项目是否合格——**项目学习的作用不是只锻炼高级思维**。学生要从项目中掌握新的技能，这种技能学习只有在学生遇到挑战的时候才最奏效。项目任务、团队行为和项目目标都应该激发学生发展新技能、构建新知识。

**项目学习 vs 基于活动的教学策略**（对比表精华）：美国内战——写考察报告 vs 就"如何使战争更加人道些？"调研并完成一组项目作品、组织辩论会；噪声污染——听声音做图表 vs 在社区确定 5 种噪声污染问题并设计可行解决方案；古代建筑——画海报 vs 以"金字塔是如何建造的？"为命题做案例分析；几何学——测量记录 vs 设计"未来的学校"图纸模型并向领导专家展示。**差异的本质**：单独的某项活动不足以应对挑战——项目学习是在**具有挑战性的背景环境中实施若干不同的活动**，把听、做、查、议等任务融入**一个有意义的命题**里。

**创设理想的学习氛围**（6 个启动步骤的最后一步）：
- **将项目和教室之外的资源建立联系**：与其他班级、其他学校、校外社区，或通过网络与远方的人建立联络，从社区组织得到指导
- **改变教室的布置**：把教室布置成办公室或实验室的样子，做区域划分，给不同小组提供专用空间——增强真实感和主人翁意识
- **三个改进学习氛围的方法**：
  1. **让学生在实践局部工作之前有全局观**——像孩子学走路先看父母怎么走、裁缝学徒先学拼布再学裁剪；"在学校里，我们学了很多具体的东西，但是它们在我的脑子里很难拼接在一起"
  2. **研究学习内容，并把它应用到实际问题中**——课堂知识传授往往用静态方式，学生不明白信息的意义；研究者发现，**没学会问题解决策略和过程的学生，很难把所学知识迁移到新环境**
  3. **使学校的学习活动更接近于现实**——Fred Newmann 等人研究 24 所学校后发现：**引入类似真实情境任务和环境的班级，学生在统考等标准化评价中得分普遍高于没有真实情境学习的班级**

## 🛠️ 落地工具：评价矩阵（50工具 《50个工具》工具9）

把"以终为始"的评价落成一张表：

```
┌───────────────────────────────────────────────┐
│  评价矩阵（《50个工具》工具9）——五列                        │
├───────────────────────────────────────────────┤
│  主产品/表现  │ 学习目标 │ 评价证据 │ 评价方式 │ 评价时机 │
├───────────────────────────────────────────────┤
│  （参考问题-任务- │（从目标体 │（能证明达 │（量规/反 │（形成性/终 │
│   产品对应表的  │ 系迁移学  │ 成的依据，│ 馈/评语/ │ 结性；具体 │
│   最后一列）   │ 习目标）  │ 如数据、  │ 打分）   │ 到里程碑） │
│              │          │ 作品质量）│         │           │
└───────────────────────────────────────────────┘
```

**评价核心三要素**（《50个工具》工具9 原文）：**谁来评价**（教师？学生自评/互评？外部专家？）、**为什么评价**（检测目标体系的达成，不是为了评价而评价——过多评价会大大增加师生负担）、**评价什么**（能体现学习目标的产品或表现才能作为评价对象）。

**评价方案相比传统作业/纸笔测试的四个特点**：
1. **形成性评价和终结性评价相结合**：三个评价时机——项目完结后（终结性）、里程碑事件完结后（形成性）、项目进行中每节课的及时反馈（形成性）
2. **教师评价和学生评价相结合**：每个学生都承担重要角色，都有评价的权利和资格
3. **自评和他评相结合**：自评是自我效能感的体现，把自评和他评对比研究可帮助学生更快进步
4. **内部评价和外部评价相结合**：内部=师评/自评/互评；外部=专家点评、产品用户反馈、公开展示听众反馈

**使用步骤**（六个步骤）：
1. 先完成"驱动问题分解表"（《50个工具》工具7）和"问题-任务-产品对应表"（《50个工具》工具8），参考对应表最后一列设计评价矩阵第一列
2. 参考 PBL 目标体系（《50个工具》工具2），把每个关键产品或表现涉及的学习目标重组迁移过来
3. 从产品或表现中找到能证明目标达成的**评价证据**，作为量规维度
4. 选择评价方式：打分量规、教师/同伴反馈、不含分值的主观性评语
5. 写清评价时机，区分形成性/终结性
6. 设定评分比例（主观性评语不设百分比）

**实例**："有爱的包装盒"项目（北京良乡中心小学）——评价对象包括平面图（几何面积体积、比例准确性，教师及时反馈+量规，里程碑2结束时，30%）、礼物包装盒（完整性/美观性/实用性/材料选择，主观性评语+优秀包装评选，里程碑3结束时，形成性）、有效沟通与合作（日常沟通/团队合作/问题解决，自评互评量规，每个里程碑结束时，30%）、成果汇报（演讲/产品设计理念/用户思维，量规+教师反馈，成果展示时终结性，40%）。**评价方案是前置的——必须在项目开始实施之前制定**（第三模块"计划筹备、整合资源"时完成）。

> 💡 **研学场景示例**（把 PBL 方法落到你的业务）：
> - **良渚研学"小小讲解员"**：主产品/表现=讲解稿+现场导览；学习目标=史料搜集+口头表达+礼仪；评价证据=讲解稿引用准确性、讲解时长与互动、观众反应；评价方式=同伴互评+游客反馈卡+导师量规；评价时机=排练后（形成性）→ 正式导览（终结性）
> - **西湖水质科考**：主产品=水质检测报告；评价证据=数据记录完整性、检测方法规范、结论与数据匹配；评价方式=科学老师量规+组间互评；时机=每次采样后反馈、终期报告会终结性评价
> - **布达佩斯展导览词创作**：主产品=导览词+现场讲解；评价证据=艺术史实准确性、故事性、与展品对应；评价方式=自评（对照标准）+师评；时机=初稿（形成性）→ 展场实测（终结性）

## 📖 案例（行动者手册）

### "海洋生物保护模拟平台"：从终点倒推的 15 周工程

**背景**：2019 年 6 月 10 日，三亚崖州湾深海区一头领航鲸生病搁浅，公益组织连夜召集十几名潜水志愿者救援，坚持 20 多个小时后领航鲸不幸死亡。这个发生在孩子身边的事件，成为项目起点。

**过程（以终为始的倒推链条）**：驱动性问题——"**如何运用所学的科学技术更好地解决传统海洋环保问题？**"最终成果——"海洋生物模拟功能性平台产品"。从终点倒推设计出"设计思维链条"：筛选实时事件 → 事件背景收集 → 事件问题分析 → 提出辩论观点 → 意向自主分组 → 产品解决方案 → 团队制作 → 迭代测试 → 成果展示。中段规划：第一阶段设计方案（按 1:10 比例绘制设计图、标注尺寸序号、制作材料清单），第二阶段制作（编程、电路、结构搭建、密封舱体），第三阶段测试迭代（游泳池和海洋实测浮力、密封、平衡）。

**结果**：公开方式包括小论文、科技节/文化节模型展示、水中实操演示。**项目评价表**把终点标准前置：自评/组内评/老师评各 0~10 分，六条标准——参与小组观点论证阐述、水下救援历史掌握、编程软件工具掌握、传感器及电路操作、平台试水操控程度、数据分析总结情况。

**启示**：这个项目是 P_7 三个领域的完美样例——**表现**（科技节展示+水中实操演示+小论文）、**技能**（编程、传感器、电路、团队协作）、**掌握任务**（物理浮力、化学水质、生物体征、地理环境、数学比例尺、语文小论文格式）。评价方案在项目前就已想清楚（自评/组内评/老师评三主体），正是《50个工具》工具9 说的"谁来评价、为什么评价、评价什么"。项目反思还印证了 P_7.1 的"修剪"原则：团队人数不统一、按角色自由搭配，设计方向可以区别化。

**题 1（改写）**：研学主题是"参观杭州博物馆"。用"以终为始"的方法：先定终点（学生产出什么作品），再倒推——写出终点、两个关键技能、两个必须掌握的"掌握任务"。

**题 3（判断）**：李老师设计的项目很有趣，但她发现"项目期间不布置作业、不考试，学生玩得很开心，只是课程标准里的核心内容基本没涉及"。请用本课内容分析问题在哪、怎么改。

<details><summary>答案</summary>

两层问题：(1) **违背"项目不是甜点"原则**——P_7 指出"通过项目来教课程"，有趣但没处理考试要考的核心内容标准，正是"多年来对项目式学习的批评"；(2) **缺少"掌握任务"领域**——倒推规划三个领域（表现、技能、掌握任务）里，她只设计了表现和部分技能。修复方法（P_7.1）：确定核心标准并写下来告诉学生；选出 2-3 个希望学生带走的大概念；把作业、测验、小论文等传统评估工具融入项目；用巴克"6A 法则"自检（学术严谨性）；学习氛围上落实"先全局观再局部"。
</details>
