## 📖 主线正文（整理自视频课 F_6.1）

### 一、先补背景："注意缝隙"（F_6）

F_6.1 开头提到上一张幻灯片"注意差距"：你可以怎么帮同事设计好项目——**通过在合适的时间问他们关于项目的关键问题，帮他们理清项目设计的思路**，这样就能避免项目失败。本课则从"项目为什么会失败"的角度切入，给你 7 个检查点。

### 二、项目失败的 7 个原因（F_6.1 核心）

**原因 1：你的学生准备好做项目式学习了吗？**
- 如果你的课堂氛围还没稳定下来，学生还没安定下来，他们可能还没准备好做项目
- 要做项目，学生需要**比较冷静，而且得有自主性**
- 如果没完全准备好，那就多花点时间**用活动来训练他们**，让他们做好准备——如果他们没准备好，项目就会乱成一团
- 记住：**这得是项目式学习，不只是做个项目而已**

**原因 2：设计循环的元素没凑齐**
- 当你看设计循环时（实践者课程讲过），确保所有元素都是项目规划的一部分：**你不能漏掉驱动性问题，不能漏掉团队合作，不能漏掉评分标准**
- 所有这些部分要一起配合，才能给你和学生带来真正高质量的项目式学习体验
- 看看设计指南，帮你把这些元素都安排好，然后专注在上面

**原因 3："覆盖陷阱"（Coverage Trap）**
- 这个挺难的：作为老师，不管你在哪儿教书，都有很大压力要让学生准备好考试、拿到高排名——那就意味着覆盖更多内容
- **项目式学习不是关于覆盖，而是关于深度**
- 确保你的项目不要内容太多：要包含一个需要解决的问题，而且真正给学生足够的时间按自己的方式去探究

**原因 4：说不清"要解决的问题是什么"**
- 说到需要解决的问题，一个很好的标准是：**你可以问自己，或者让别人问你——你正在设计的项目里要解决的问题是什么？你应该能直接回答出来。这就是学生在解决的问题。**
- 如果你答不上来，就回到你的规划里，再看看学生在这个项目中到底在做什么、他们在解决什么问题
- **记住：项目式学习是从问题式学习来的。一个好的项目式学习的核心就是一个问题。**

**原因 5：团队失败 → 项目失败**
- 当团队失败时，项目就失败了——这就是为什么 Tom 花很多时间在团队上：**如果团队不对，项目就不对**
- 你必须确保花必要的时间来组建合适的团队，使用团队工具，和学生聊他们的团队，跟进并指导
- 让他们起草和设计，让他们测试彼此的经验，**关注每个团队成员的责任感和职业道德**，这样就不会有人偷懒不干活
- 团队真的是好项目的关键

**原因 6：评分标准设计得太晚**
- Tom 跟很多做项目的老师聊过，问他们评分标准，他们说："哦，我回头再弄，我晚点在项目里设计评分标准。"
- **评分标准需要在项目进入课堂之前就设计好**——设计出来可以跟学生分享，这样学生就知道对他们的期望是什么
- 然后你给他们列出项目期望——这就是评分标准的作用：**它们不只是评估工具，它们是训练和组织工具**

**原因 7：项目里没有"为什么"**
- 确保项目里有 Tom 所说的"为什么"：想想你的项目——我这么做是有原因的吗？整体的愿景是什么？
- 这又回到了年初要为你的学生设定愿景：你希望学生能从中得到什么？他们经历了这个项目之后会变成什么样？
- **有时候我把项目比作伟大的小说：一旦你读了它，或者经历了一个项目，你就变成了一个不一样的人。**这真的是你希望学生达到的效果——你希望他们带着不同的思维方式、不同的视角，以及对自己作为学生有不同认识地走出来

**总结**：如果你把这些元素都安排好了，你就会有很棒的项目；如果你没有，你就会遇到某种问题——也许项目不会失败，但对你或学生来说，它们可能不会像你期望的那样令人满意。所以，**请回顾这些特质，看看你的项目，确认它们是否融入了你的设计。**

## 📚 深度阅读（书籍精华）

### 巴克《项目学习教师指南》第 5 章——管理项目过程

**教师在项目中的角色（项目管理者）**：指导项目学习的教师必须能够成功地管理好项目学习的过程——这需要使用一些工具和策略方法，使项目过程结构完整、可进行评价。关键管理任务：

1. **自始至终引导学生聚焦在项目目标上**：不仅在项目开始，而且随着项目进展，定期强化项目目标——通常考虑使用项目的驱动问题，保持学生的目标导向和参与积极性；提醒学生深入的学习需要时间和耐心
2. **对学生进行适当的分组**：协作可以有不同形式（小组/大集体/先独立后合作/随进展改变分组）
3. **组织每天的项目学习活动**：帮助学生确定探究范围和学习任务，设定任务完成期限，收集过程文件，给予必要反馈
4. **监控和管理学生的行为**：教学生如何在没有监管的情况下有效工作——时间期限的概念、做事的要求和标准、时间管理方法（每日目标计划单、最后期限表）
5. **管理工作流程**：及时收集作业、关注进展、判断学生是否在通往成功的道路上；注意学生觉得困难的内容；**如果有必要，教师可以停下来给予即时指导**（小讲座、讲义资料）提供知识补给，推动项目进展
6. **评估项目的成功**：帮助学生认识到从项目中有哪些收获、还有哪些没有学到

**设计检查点和里程碑（防失败关键）**：项目管理方法把项目分成若干单独的部分，可以独立对各部分进行更新。有用的方法：要求小组长作非正式简要报告；布置快速书面评论；随机或有选择地与学生会谈；举办每周例会组织小组或全班反思；审阅项目工作检查清单；检查项目日志；教师写自己的项目日志；参与到项目小组中监督进度；在活动完成时组织简要汇报。项目进展可以关注：理解上的问题、个人或小组的进展、参与积极性、出现的问题或成功、意外的收获、新策略、对资源的需求。

**两个核心工具**：
- **"知道/需要知道"清单（Know/Need-to-know list）**：两大白纸架分成两列——学生分组列出所有已知信息和需要调研的信息；随着调研进行，表单内容不断添加或删减。帮助学生在开始阶段就了解项目特征
- **学习日志（Learning log）**：记录调研活动的进展、困惑与突破——是非常好的项目过程文件

**项目最终评估 4 个方法**：全班情况通报会（选一名学生做辅助者引导全班讨论）；鱼缸式讨论法（小组坐进大圈中间通报，外围同学倾听并偶尔参与）；问卷调查；自我评价。别忘了**庆祝会**——邀请家长、社区成员、其他教师参加，让学生拥有成就感。

## 🛠️ 落地工具：会议纪要 + 要事第一（50工具 工具46/45）

**工具 46 会议纪要**——项目管理中的重要工具，记录每一次团队会议的参会人员、关键议题、达成的决议：

```
┌──────────────────────────────────────────────────────┐
│  会议纪要模板（工具46）                                │
│  一、基本信息：会议名称/日期/地点/记录人/召集人/        │
│               开始时间/持续时间/审核人                  │
│  二、会议目标（期望达到的结果）                        │
│  三、参加人员（姓名 + 在项目中的头衔或角色）            │
│  四、发放材料（会议讨论的所有项目资料）                │
│  五、发言记录（发言人观点、意见和建议）                │
│  六、会议决议（结论；哪些达成一致、哪些没有、           │
│               解决方案是什么）                         │
│  七、会议纪要发放范围                                 │
└──────────────────────────────────────────────────────┘
```

**为何使用**：很多职场新人承担的第一份工作就是做会议纪要，但在走出校园前大部分学生没接触过——记录信息不全、理解偏差是常事。做会议纪要要求**仔细倾听、提取关键信息、及时记录**。每一份会议纪要都代表了团队的智慧，展示了项目的进展，是宝贵的过程性资料。

**使用步骤**：① 确定记录员（更推崇轮流记录，让每位学生得到锻炼）；② 设计会议纪要模板（每个项目一份通用模板）；③ 培训记录员（教会捕捉关键词的方法）；④ 请记录员记录（学生习惯后也会应用到没有教师参与的讨论中）；⑤ 审核会议纪要（像语文老师批改作文一样发现记录中的问题）；⑥ 发送会议纪要（会议结束后尽快发给所有相关人员）。

**工具 45 "要事第一"原则**——史蒂芬·柯维《高效能人士的七个习惯》中的四象限时间管理：

```
┌──────────────────────────────────────────────────────┐
│  四象限（工具45）                                     │
│  重要且紧急：危机、迫切问题、限时任务                  │
│  重要但不紧急：预防性措施、建立关系、制订计划、休闲    │
│  不重要但紧急：某些电话、邮件、写报告、迫切事务        │
│  不重要且不紧急：琐碎忙碌的工作、消磨时间的活动        │
│  要事第一：花大部分时间在第二象限（重要但不紧急），     │
│  第二象限处理得越好，进入第一象限的"救火"越少          │
└──────────────────────────────────────────────────────┘
```

**为何使用**：管理时间本质是管理事件。缺乏时间管理能力的人总是被"截止日期"追着跑；时间管理能力强的人可以成为时间的主人。

**使用步骤**：① 把大项目拆成里程碑、里程碑拆成子任务，制成工作计划表；② 和学生一起把拆分后的事件写在小纸条上，汇成"事件池"；③ 为每个事件做两个标签——截止日期和重要性（非常重要/重要/不重要）；④ 在**每个项目里程碑结束后的定期工作会**上开展"要事第一"讨论（事件的重要性和紧急性是动态变化的）；⑤ 把讨论结果更新进工作计划，让团队聚焦第二象限。

> 💡 **研学场景示例**：
> - 西湖水质项目 → 用**会议纪要**记录每次团队例会（采样方案、分工、数据进展），用**要事第一**给"设计采样方案（重要不紧急）"排到"帮同学买水（不重要不紧急）"前面
> - 良渚策展项目 → 每个里程碑（选题/资料/展陈设计/布展）结束时开**例会 + 会议纪要**，用四象限清理"打印任务单（紧急）"与"设计访谈提纲（重要）"的优先级
> - 布达佩斯展导览项目 → 跨组协作时用**会议纪要**同步各组进度（音频组/文案组/排版组），防止"团队失败"这个项目杀手

## 📖 案例（行动者手册）

### 校园贸易节编程产品项目：当老师预见"输出不理想"时

**背景**：杭州一所公办小学的编程社团，学生在六一前要为校园贸易节设计一款可盈利的编程产品。老师设计这个项目的动机很明确：之前的学习"缺乏面对冲突、面对失败、面对不确定性等问题的锻炼"——项目恰好提供这些锻炼。4 周（2 课时/周），20 人分四组（3-7 人，自由组队），1 主教 + 1 助教。

**过程**：分组时出现了教科书式的"团队风险"：出现了 7 人大团队；**有 3 个学生没有加入任何团队**——如果把他们塞进任何一个团队，"基本上就是打酱油的状态，会游离于团队之外"。老师"毅然决定让这 3 个学生单独成立一个团队"。"虽然已预见到该 3 人团队的输出将可能并不理想，但相对将他们分配到任何团队内的状态，相信单独让他们成立一个团队，对于这几位学生来说，会更有收获一些。"团队按 CEO/CTO/CFO/COO/CIO 角色分工；老师提醒学生：技术上框定在已学内容、预算上先搜淘宝物料价格控制成本——防止"覆盖陷阱"和预算失控。产品开发阶段"老师没有过多的指导，多是作为观察者的角色从旁提供协助"（对应 F_6.1 原因 5 的解毒剂：关注责任感但不过度干预）。四个团队最终的产品方向与盈利模式：老潘队（游戏机，玩游戏赢奖品）、星期五队（游戏机）、呵呵哈队（智能学习桌，付费体验盈利）、詹姆斯队（自动浇水机，付费体验盈利）。

**结果**：产品在校园贸易节上展示和营销。项目评价看重"学生的尝试、探索、反思"——"相比最终完善的产品输出，学生们在这个过程中的尝试、探索、反思更重要"。

**启示**：这个案例正面处理了 7 个失败原因中的好几个——它把"冲突、失败、不确定性"设计进项目（不回避）；对 3 人团队用"独立成组"化解"游离打酱油"（团队失败预防）；用角色分工和观察者姿态管理团队；用"过程比产品更重要"的评价守住项目的"为什么"。**它证明：预见到失败风险并主动设计应对，项目就不会失败。**

**题 1（改写）**：老师想把"带学生做西湖水质检测"做成项目，初稿方案是"每周检测一次水质，记录数据，期末交报告"。请找出其中的失败隐患并改写成防失败方案。

初稿隐患：没有驱动性问题（原因 4——说不清要解决的问题）；没有团队设计（原因 5）；没有评分标准（原因 6）；没有"为什么"（原因 7）。

**题 2（判断）**：以下哪个做法更能防止项目失败？
A. 开学第一周就宣布项目，让学生马上开工，边做边补评分标准
B. 开学先用活动训练学生的自主性和协作规范，项目启动前把驱动问题、团队、评分标准设计齐

<details><summary>答案</summary>

B。原因 1（学生没准备好：需要冷静 + 自主性，要先训练）和原因 6（评分标准要在项目进入课堂前设计好）同时支持 B。A 同时踩了原因 1、原因 2（设计循环元素缺失）、原因 6 三个坑。
</details>

**题 3（判断）**：同事的项目已经做了一半，你问他"这个项目要解决的问题是什么"，他支支吾吾说不上来。请分析这个信号，并给出建议。

<details><summary>答案</summary>

两层分析：(1) 表层是表达问题，深层是**设计问题**——F_6.1 说"你应该能直接回答出来，这就是学生在解决的问题。如果你答不上来，就回到你的规划里，再看看学生在这个项目中到底在做什么、他们在解决什么问题"；(2) 这往往和"覆盖陷阱"（原因 3）连在一起：项目塞了太多内容，却没有核心问题。建议：回到项目规划，和学生一起梳理"我们到底在解决什么"，必要时砍掉与核心问题无关的活动；也可以像 F_6（注意缝隙）那样，用关键提问帮同事理清思路。
</details>

**题 4（自查·本课产出）**：拿你正在设计或已实施的一个项目做"失败体检"：
1. 逐条对照 7 个原因，标出你的项目最危险的 2 个
2. 为每个危险项写一条预防动作
